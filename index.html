About me

The person behind the pull requests.

S VeerendrareddySoftware Development Engineer · Halodoc

I joined Halodoc in February 2024, right after my B.Tech in Information Science at NIE, Mysuru. I started on the web team, building the Angular apps that patients and ops teams use every day. Then I moved to the backend, to the systems that settle money between pharmacies, insurers, payment gateways and banks.

That work taught me to put correctness first. A missed record means someone gets paid the wrong amount, so I read the query plan, write the tests, and check the backfill myself.

Starting on the web shaped how I build backends. I think about the person waiting at the other end of every API, whether it's a patient loading a page in under 2.5 seconds or an ops team waiting on a 13-second API that shouldn't be slow.

And I like building tools for other engineers. The Claude Code agents I built help my whole team find and fix slow queries, with the tests and merge request included.

LCP on halodoc.com/tanya-dokter, the flagship Chat-with-Doctor page

I removed a double SSR-hydration API fetch with TransferState, injected a high-priority preload for the LCP image during SSR, and replaced a third-party lazy-loading grid with my own eager-first component. I found the root cause by auditing compiled bundles without access to the library's source.

I root-caused 5–13 s APIs and Kafka consumers: a missing selective index, blocking work on the Kafka poll thread, and a synchronous batch job on the request thread.

Hibernate · batching

Removed N+1 queries across 4 reconciliation microservices

I replaced per-row lookups with batched IN (...) preloads and bulk writes. I deliberately kept IDENTITY-keyed inserts unbatched, because Hibernate disables JDBC batching for them and their IDs feed downstream Kafka events.
